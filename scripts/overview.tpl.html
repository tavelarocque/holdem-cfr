holdem-cfr

A counterfactual regret minimization solver for heads-up no-limit Texas hold'em, built from scratch in Rust. It covers the same pieces as Libratus and Pluribus at laptop scale: an abstracted blueprint trained by Monte Carlo CFR, an exact range-vs-range postflop solver, and a measurement stack that reports how exploitable the result is.

Every layer is checked against something it cannot fake: closed-form equilibria, published game values, brute-force enumeration, or an independent implementation.

Results

From exact solutions to measured approximations

Small games are solved exactly and verified with a full best response. The full game is too large for that, so the blueprint is measured with local best response, which finds a lower bound on how much a counter-strategy can win.

What the measurements caught

Three findings the tests forced

A cross-check that missed bugs

The postflop solver was checked against an independent scalar implementation, and deliberately injected bugs were used to test the check itself. It first caught only one of three: the test ranges had no tied hands and no shared combos, so those code paths never ran. Adding them made all five injected bugs fail the test.

Float precision past 2²⁴

A checkpoint trained 12× longer lost to a shorter one by a statistically clear margin. The cause was 32-bit accumulators: past about 8 million, adding a probability like 0.3 rounds to nothing, so 3.4% of the strategy table had silently stopped averaging. Switching to 64-bit fixed it at no speed cost.

Head-to-head stops ranking

Matches between checkpoints became intransitive: A beat B, B tied C, C beat A. Near equilibrium, a match measures how leaks line up, not quality. Local best response ranked them instead, and showed that more training was no longer the bottleneck.

Limits, stated plainly: the blueprint plays an abstracted game with a fixed bet menu and no real-time search, and local best response gives a lower bound, not the true exploitability. Real-time re-solving of the turn and river with the exact solver is the next milestone.
